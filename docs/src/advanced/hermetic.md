# Hermetic Builds

Hermetic builds ensure reproducibility by eliminating external dependencies and
non-determinism. This is essential for build systems like Bazel and Buck2.

## What is Hermetic?

A hermetic build:

- Uses exact versions from a lockfile
- Does not access the network (in strict mode)
- Produces identical outputs given identical inputs
- Fails explicitly rather than using fallbacks

## Hermetic Levels

Configure in `antlers.toml`:

```toml
[hermetic]
level = "strict"
```

### disabled (default)

No hermetic enforcement. Normal operation.

```toml
[hermetic]
level = "disabled"
```

### reproducible

Requires a lockfile but allows network access:

```toml
[hermetic]
level = "reproducible"
```

- Resolution must match lockfile
- Network is used to fetch artifacts
- Checksums are verified

### strict

Full hermetic mode - no network access:

```toml
[hermetic]
level = "strict"
```

- All artifacts must be in cache
- No network requests allowed
- Fails if any artifact is missing

## Lockfiles

Generate a lockfile to capture exact versions:

```bash
antlers lock
```

This creates `antlers.lock`:

```toml
# This file is auto-generated. Do not edit.
version = 1

[[artifacts]]
coordinate = "com.google.guava:guava:33.0.0-jre"
sha256 = "abc123..."
repository = "central"

[[artifacts]]
coordinate = "com.google.guava:failureaccess:1.0.2"
sha256 = "def456..."
repository = "central"
```

## Required Configuration

For strict hermetic mode, you need:

```toml
[hermetic]
level = "strict"

[cache]
path = ".antlers/cache"  # Explicit path required
mode = "read-only"       # Prevent cache modifications

[env]
allow = ["GITHUB_TOKEN"]  # Explicit env var allowlist
```

## Workflow

### Initial Setup

```bash
# 1. Resolve dependencies (populates cache)
antlers resolve org.jetbrains.kotlin:kotlin-stdlib:2.0.0

# 2. Generate lockfile
antlers lock

# 3. Commit both
git add antlers.toml antlers.lock .antlers/cache
git commit -m "Add hermetic dependency configuration"
```

### CI/Build

```bash
# Strict mode - fails if anything is missing
antlers resolve --hermetic strict
```

## Vendoring

For fully offline builds, vendor the cache:

```bash
# Populate cache
antlers resolve --all

# Vendor to project
cp -r ~/.antlers/cache .antlers/cache

# Configure vendored cache
[cache]
path = ".antlers/cache"
mode = "read-only"
```

## Environment Variables

In hermetic mode, only explicitly allowed variables are available:

```toml
[env]
allow = ["MAVEN_USER", "MAVEN_PASS"]
```

Referencing any other variable fails:

```
Error: Environment variable 'UNKNOWN_VAR' is not in the allow list
```

## Integration with Build Systems

### Buck2

```python
# BUCK

load("@prelude//java:java.bzl", "java_library")

# Dependencies resolved by antlers
java_library(
    name = "deps",
    deps = [
        ":guava",
        ":kotlin-stdlib",
    ],
)
```

### Bazel

```python
# WORKSPACE

load("@bazel_tools//tools/build_defs/repo:http.bzl", "http_file")

# Generated by: antlers resolve --format bazel
http_file(
    name = "guava",
    sha256 = "abc123...",
    urls = ["https://repo1.maven.org/maven2/com/google/guava/guava/33.0.0-jre/guava-33.0.0-jre.jar"],
)
```

## Troubleshooting

### Missing artifacts in strict mode

```
Error: Artifact not in cache: com.google.guava:guava:33.0.0-jre
```

Solution: Pre-populate cache in non-strict mode first:

```bash
antlers resolve --all  # Populates cache
antlers resolve --hermetic strict  # Now works
```

### Lockfile mismatch

```
Error: Resolved version differs from lockfile
  Expected: com.google.guava:guava:32.0.0-jre
  Got: com.google.guava:guava:33.0.0-jre
```

Solution: Update the lockfile:

```bash
antlers lock --update
```
